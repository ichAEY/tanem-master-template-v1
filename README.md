# TANEM Master Template v1

Единый производственный шаблон TANEM для сайтов мастеров и студий.

## Принцип

Новый клиент не получает новый дизайн. Мы используем один утверждённый каркас TANEM, меняем только проверенные данные, фотографии, услуги, ссылки и предусмотренные режимы блоков.

Визуальная база зафиксирована на `ichAEY/claytone-current` commit `ce1bd42b44e76e1851af9e069c4cbcf06fc8eac2`. Поверх неё применяются два универсальных слоя TANEM:

1. `scripts/apply-tanem-template.mjs` — структура портфолио, услуги, категории, акции и tactile-состояния;
2. `scripts/apply-tanem-final.mjs` — финальная логика мастера/студии, пустых данных и последние утверждённые refinements Тахмины.

## Режим профиля

В `site-data.mjs`:

- `profileType: "master"` — частный мастер;
- `profileType: "studio"` — студия/салон.

Студия не должна автоматически называться «мастером». Неизвестный стаж, рейтинг и количество отзывов оставляются пустыми — интерфейс уберёт эти элементы без дырок.

## Услуги

- `serviceMode: "simple"` — два обычных направления, например «Маникюр / Педикюр»;
- `serviceMode: "categories"` — несколько самостоятельных направлений с утверждённой лентой категорий.

Количество отдельных процедур не определяет режим.

## Портфолио

- блока «до / после» нет;
- в превью всегда 5 работ;
- две дополнительные фотографии находятся под основной композицией;
- нижняя пара равная по ширине;
- затем кнопка «Открыть галерею»;
- остальные работы доступны в полной галерее.

## Акции

`promotions: []` полностью убирает блок акций. Неподтверждённые акции не добавляются.

## Фотографии

Workflow принимает JPEG, PNG и WEBP. **Нельзя просто менять расширение файла.** Если фотография является PNG, она должна называться `.png`, а не `.jpg`.

Пример:

```text
assets/
  images/
    master.png
    logo.png          # если есть
    portfolio/
      01.png
      02.png
      03.png
      04.png
      05.png
      ...
```

JPEG можно аналогично хранить как `master.jpg`, `01.jpg` и т. д. Пути в `site-data.mjs` должны совпадать с реальными именами файлов.

## Новый сайт

1. Создать новый репозиторий из шаблона.
2. Заполнить `site-data.mjs` только проверенными данными.
3. Выбрать `profileType` и `serviceMode`.
4. Загрузить `master` и минимум 5 работ с правильными расширениями.
5. Оставить `promotions: []`, если подтверждённых акций нет.
6. Включить GitHub Pages → Source → GitHub Actions.
7. Проверить desktop, laptop и mobile.

## Системное правило

Ошибка конкретного клиента не должна лечиться одноразовым костылём, если причина находится в фабрике. Системная проблема сначала исправляется в этом репозитории, после чего клиент пересобирается из обновлённой версии.
